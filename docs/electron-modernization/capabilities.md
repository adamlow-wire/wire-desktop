## Coverage interpretation

CAP-001 draft native reload/About checkpoint: controller tests verify all-account reload with exact session/cookie retention, preserved selection, queued-authority revocation and healthy-account recovery after partial failure. About's actual request path uses the main-owned native binding; version requests remain tied to the account selected when invoked. These local tests strengthen DCP-002/DCP-004 without establishing final cross-platform cutover acceptance or changing confidence ratings.

SEC-012 preview contract: public default-port HTTP(S) only; no cookie replay or ambient proxy/account credentials. Private, authenticated-proxy and cookie-challenge previews may be unavailable without affecting ordinary login/backend traffic. Known title/description/site/type/URL and image fields, entities and title/first-image fallback remain compatible; arbitrary metadata paths and unused audio/video trees are excluded. PR #44 passed all final-head gates and merged as `62435cc6`; SEC-012 is complete without claiming broader certificate/configuration or M3 closure.

SEC-008 merged in PR #38 after all hosted gates passed. Main creates SSO windows because renderer-created children do not adopt the requested isolated session. Desktop close/focus and initiating-page cleanup are covered, but the window has no opener: the backend's normal web verdict still uses `window.opener.postMessage`, so successful IdP completion is not established. CAP-002 now reproduces and repairs that path locally using native redirects without restoring opener privileges; the one-time callback and cookie-scope tests pass. PR #43 passed final-head all-platform packages and authenticated Windows/macOS E2E before merge. Controlled live IdP evidence remains required. HTTPS enterprise IdP navigation remains supported; local HTTP initial origins remain available for deterministic fixtures. PiP preserves calling's empty/about:blank window, and account navigation/redirects remain on the registered origin.

SEC-006 checkpoint (2026-09-08, [PR #37](https://github.com/adamlow-wire/wire-desktop/pull/37)): all-platform package and authenticated Windows/macOS E2E gates passed with explicit OS sandboxing. Image copy is main-owned; save-image retrieval retains the account session. The `environment` bridge exposes read-only metadata/lookups, not settings mutation or main-process policy/diagnostic helpers. Bundled preloads use console diagnostics, not filesystem writes. This closes sandboxing, not the remaining capability-specific packaged/manual obligations.

SEC-005 checkpoint (2026-09-07, [PR #35](https://github.com/adamlow-wire/wire-desktop/pull/35)): isolated immutable compatibility APIs and fixed event adapters now have real-Electron tests. Authenticated Windows/macOS login, multi-account, logout, menu, notification, and calling E2E passed, alongside package baselines on all three platforms. Windows needed one unchanged rerun after a notification timeout. These results strengthen DCP-001–DCP-008 and DCP-013–DCP-016 without raising their confidence ratings: sandboxing, production view migration, platform key stores, and the listed packaged/manual obligations remain open.

A capability cannot reach `high` confidence solely through unit mocks. Security-sensitive capabilities also require the corresponding invariant tests. A platform-independent policy may be tested once, but each native integration must have representative evidence on every platform claimed in its row.
