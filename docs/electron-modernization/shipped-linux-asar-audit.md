# Unsigned Linux ASAR package inventory

Status: **partial ELC-003 / PKG-001 evidence**, 2026-09-23. Source is the local composed candidate `2ba7ade3e43bca9c5263c1bf5b7fa8ac54b20acd` (tree `484448fee75fc5d311f3d73b9b35fff8f9f206d635`) on Electron 43.4.0. This is an unsigned Linux `dir` target built with the repository's actual `buildLinuxConfig` and `electron-builder`, without launching the app. It is not an AppImage, deb, rpm, Windows or macOS artifact.

The built `linux-unpacked/resources/app.asar` has SHA-256 `d765a4ce82ec18af069361369c5b092f0977ce4a84fad7c3b50a979986d57a04`. `node bin/test-tools/verify-package-contents.cjs wrap/recovery-artifacts/linux-dir` passes: 7,695 ASAR entries and all 22 required files. The local-only [inventory utility](../../bin/test-tools/inventory-shipped-asar.cjs) finds **423 installed package instances / 366 distinct names**. It accepts only actual `node_modules` package-root manifests; 93 nested `package.json` metadata files lacking name/version are excluded. The four `package.json` files under `app.asar.unpacked` correspond to the same four package paths in the ASAR inventory. The private detailed inventory and unsigned application directory remain in ignored local `wrap/recovery-artifacts/linux-dir`; they are not committed.

The maintainer explicitly approved a metadata-only query of these 423 package instances to [npm's bulk advisory endpoint](https://docs.npmjs.com/cli/v8/commands/npm-audit/). An initial automatic approval review rejected that query before approval; the approved query then completed twice with identical detailed matches at 2026-09-23T09:43:23Z and 09:47:27Z. It returned **30 version-range matches: one critical, 22 high, five moderate, two low**. The affected names are `tar`, `minimatch`, `brace-expansion`, `semver`, `ip`, `uuid` and `@tootallnate/once`. Detailed matches are kept in a private ignored local JSON file, not committed. Matches establish package/version overlap, not that an application execution path reaches a vulnerable API.

The critical match is shipped `tar` 6.2.1 against [GHSA-23hp-3jrh-7fpw](https://github.com/advisories/GHSA-23hp-3jrh-7fpw), which describes unbounded extraction of untrusted archives. Eight more high matches involve the same `tar` version. `minimatch` 3.1.2/5.1.6 and `brace-expansion` 1.1.13/2.0.1 account for 12 high matches; `semver` 7.5.0 and `ip` 2.0.1 account for one each. The top-level app manifest does not directly declare those five packages; ASAR manifests show `tar` under the `node-gyp`/`cacache` tree, for example. Preliminary declared-dependency traversal does not connect the high/critical instances from the app's 30 root dependencies, but dynamic/peer loading and packaging inclusion still require review. Do **not** use this preliminary observation to accept the findings. The shipped graph also includes `uuid` 9.0.1, a moderate version-range match; the two reviewed app callers use argument-free v4, outside that advisory's supplied-buffer v3/v5/v6 behavior. Transitive callers are not yet disposed.

**ELC-003's no-unaccepted-high/critical acceptance is open.** The earlier installed-production audit counted 354 instances and found no high/critical matches, but it did not represent the 423 instances in this ASAR. The package-content verifier checks first-party inputs and required files; it does not prune or clear all third-party package contents.

Reproduce after building the same unsigned Linux directory with the current builder configuration:

```sh
node bin/test-tools/verify-package-contents.cjs wrap/recovery-artifacts/linux-dir
node bin/test-tools/inventory-shipped-asar.cjs wrap/recovery-artifacts/linux-dir/linux-unpacked/resources/app.asar wrap/recovery-artifacts/linux-dir/shipped-packages.json
node bin/test-tools/query-shipped-advisories.cjs --allow-public-npm-metadata-query wrap/recovery-artifacts/linux-dir/shipped-packages.json wrap/recovery-artifacts/linux-dir/shipped-advisory-matches.json
```

The inventory command reads the ASAR locally, writes its package names/versions to an owner-controlled file with mode `0600`, and prints only hash/counts/path. It makes no network request. The separate, explicit-opt-in query command sends those names/versions to public npm, writes detailed matches mode `0600`, and prints only aggregate counts/path. The build ran on pinned Node 22.22.3 and locked dependencies. The local build command avoided `build:prepare` because that script clears the shared `wrap` directory containing protected worktrees.

Next ELC-003/PKG-001 work: trace the included high/critical package trees and why they enter the ASAR, remove unneeded installed packages from package inputs or update required ones compatibly with behavior tests, then rerun the shipped graph audit on the final composed artifacts. Document any specific non-applicable match with a reviewed call path rather than accepting all included packages as safe. PKG-001/TST-005 must still qualify actual unsigned installers and packaged native startup on all three platforms. The current ASAR does not close either gate.
